### Shipping

只有用户明确要求合并、发布或落地 PR 时使用。绿色 CI 不是充分条件。

1. 确认用户授权的准确范围，包括 PR、仓库、合并方式和是否允许 auto-merge。
2. 对每个待合并 PR 记录当前 head SHA、base SHA、diff 和必需检查。
3. 独立验证真实行为。多 Agent 验证只有在用户明确要求时启动，否则由主 Agent完成。
4. 只合并从依赖根部开始连续通过验证的一段。遇到第一个未验证 PR 即停止。
5. 合并前重新读取 PR，确认验证仍对应当前 head SHA，且没有新增阻塞线程或失败检查。
6. 一次只处理一个 PR。执行合并后读取平台返回值，确认实际状态为 merged，再处理下一个。
7. 不 force-push、不关闭他人的 PR、不更改保护规则，除非用户明确授权具体操作。
8. 需要等待检查或队列时使用 heartbeat automation，并只在状态变化、失败、完成或需要用户决定时通知。

输出已验证范围、实际合并的 PR、未合并的第一个缺口、使用的合并方式和平台确认结果。
