# Arena

同一任务生成多个独立候选方案，再选出最佳基础并吸收其他方案的优点。

## 使用条件

只有用户明确要求多 Agent、多方案竞争、平行原型或点名 `$arena` 时才启动。普通设计任务不自动扩展为 Arena。

## 工作流

1. 明确每个候选要产出的同一种制品。
2. 写出 3 至 6 条可以逐项判断的评分标准。
3. 为每个候选建立独立写入位置。多个候选不得写同一文件、分支或状态。
4. 使用 Codex 子 Agent 协作能力同时启动候选。默认继承当前模型，不假设特定模型名称。
5. 等待全部候选完成。失败的候选可重试一次，之后记录缺口并继续。
6. 主 Agent 必须完整阅读每个候选。必要时再启动一个只读评判 Agent。
7. 按评分标准选择基础方案。不要凭整体印象选择。
8. 将落选方案中确实更好的部分重新设计后合并，不能机械复制。
9. 对最终制品运行与普通交付相同的真实验证。

## 输出

交付一个最终制品和一份简短综合记录。记录基础方案、吸收内容、舍弃原因、候选缺口和验证结果。
